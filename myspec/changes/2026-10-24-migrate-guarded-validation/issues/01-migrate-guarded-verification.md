**What to build:** 仓库维护者从既有统一验证入口获得可信的新模式结果：普通检查实际受保护、必要真实链路仍完整、按领域选择与缓存保持有效、工具与持续集成身份一致，而不改变生产量化行为。

**Blocked by:** 无前置票据。预算及完整开始开发门禁已获明确批准，可在同一分支按已确认范围实施。正式工具步骤前核实选定环境与量化项目依赖；配置最终写入确认只阻塞实际覆盖配置：届时须展示精确清单并取得明确确认，不作为前期代码开发的前置条件。

**Status:** ready-for-agent

完整开始开发门禁已确认，实施进行中；项目环境与正式工具执行仍须按所列前置核查。

## 为什么保留一张票

测试内存化、原生边界分类、新配置与工具自举相互耦合。为了拆票而临时将未知旧整组列为真实检查，会让中间通过失去保护含义。因此票内按领域做红绿循环，只在同一公开统一入口完成收口后验收；完成后进行独立审查。

## 验收条件

- [x] 完整开始开发门禁明确固定基线、同一工作树、完整功能分支、串行实施方式、单票独立审查和最高公开测试接缝，并取得展示后的确认；并发按用户更正为 4×4 先行。
- [ ] 落实用户已批准的新版本机 60 秒总预算硬截止：快速与完整验证包含准备、缓存选择和执行，到期终止本次进程树、停止后续检查并失败；开启本机强制预算，不新增单项 3 秒限制。云端/拉取请求/持续集成保持工具原策略，配置及正式规格候选一致。
- [ ] 保留现有统一入口与项目虚拟环境；构建检查保持真实空集，不引入占位构建或替代验证脚本。
- [ ] 首先通过同一公开入口记录可复现红灯，完成最小迁移后重跑同一检查转绿；定向定位结果不冒充正式验证。
- [ ] 逐项登记旧测试意图的保留、内存化、聚焦真实化、去重或低收益删除。已授权的重复独立 JIT 去重无需重问，公式仍在；其他删除项说明原覆盖、替代覆盖及真实覆盖变化，若实质减少唯一覆盖或能力，先说明原因、收益、成本及影响并获用户明确批准，无静默漏收。
- [ ] 落实另行批准的两组删减并披露覆盖损失：晋升链接边界 18→4、结果包磁盘矩阵 22→11；不删除其他唯一语义。
- [ ] 契约、解析、纯计算和可内存化错误路径尽量归普通检查，实际产生保护证据；导入、准备和清理阶段不绕过保护。
- [ ] 普通路径不因无关的提前导入触发 DuckDB；只在既有实际数据库边界做最小延迟导入，不建模拟框架、不改变公开接口。
- [ ] DuckDB 及文件 SQLite 按真实边界处理；SQLite 内存能力按工具现有保护运行，付费预览一次性消费未遗漏。
- [ ] 原生 Python 文件与数据、Chromium/Windows 会话、Git/PowerShell 共享虚拟环境三类保留最小真实成功主路与必要失败/恢复覆盖，不做整组未知豁免或大型矩阵。
- [ ] 核心量化端到端路径仍经公开入口完成行情导入、快照、运行、结果固化、复用/冲突与晋升；标准策略分析经独立公开运行与报告入口验收；工作树环境仍由真实工具验收。
- [ ] 最大外并发改为 4，仅保留既有工作树检查内并发 4，其他检查不新增内并发；线程与业务子进程另行核算。禁自动加载插件、显式加载必要插件，无依赖升级或新增 3 秒单测限制。
- [ ] 路径选择与缓存按现有领域保持独立，命令读取范围、配置与共享夹具变化能正确触发相关检查；不合成单一巨型测试命令。
- [ ] 删除重复且误导的独立 JIT 检查，普通公式覆盖仍在；生产即时编译及正式编译要求未变，不新增或谎称完成真实 JIT 编译验收。

- [ ] 新配置与持续集成自举使用兼容的同一正式工具身份，独立工具链工作流硬编码的旧构建验证源码也同步；不擅自切换开发/发布模式。Ubuntu 干净工作树快速验证若跳过，只计工具链/结构证据，不当 Windows 正式验收，不增加矩阵。
