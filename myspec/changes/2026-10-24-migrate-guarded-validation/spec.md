## Problem Statement

量化仓库现有统一验证使用旧配置。大量契约、解析、计算和错误分支验证与真实文件、数据库、子进程或浏览器准备混合，不能证明普通检查在无副作用保护下运行。部分检查以宽泛名称筛选或重复启动同一公式测试，既降低验证反馈效率，也让检查名称与实际证据不一致。

迁移不能靠把所有旧检查登记为真实检查、静默漏收测试、放宽预算或假造构建来换取通过。也不能因迁移验证而改变生产量化计算、正式回测边界或现有数据与结果契约。

## Solution

以现有构建与验证统一入口迁移到显式声明真实检查的新配置。普通检查尽可能只进行内存计算和必要静态读取，并实际接受工具的运行时保护；只有不可替代的环境行为保留为聚焦真实检查。真实覆盖围绕原生 Python 文件与数据链、Chromium/Windows 会话、Git/PowerShell 共享虚拟环境三类现有边界，保留每领域/场景一条最核心真实链及链内必要断言，不另造调度框架或大型集成矩阵。

按现有领域保留独立检查选择与缓存。配置与持续集成中的工具身份同步更新，正式配置只经官方初始化入口写入、备份和校验；无法在云端执行的新版工具或 Windows 验收交由已授权的本机工具步骤，不把整个开发任务搬到本机。

## User Stories

1. 作为仓库维护者，我希望普通验证实际启用无副作用保护，以免测试准备或导入阶段悄悄写盘、联网或启动业务子进程。
2. 作为维护者，我希望纯契约、解析和计算测试优先使用内存输入，以便保留行为判断而不为低收益的物理夹具支付成本。
3. 作为维护者，我希望真实检查有明确、聚焦的外部环境理由，以免把普通测试整组豁免后仍误称已保护。
4. 作为研究者，我希望共享行情导入、快照、本地研究、结果固化与晋升仍从既有公开入口完成真实核心主路，以免单元测试通过掩盖链路故障。
5. 作为归档使用者，我希望归档、查询、文档同步和浏览器会话的必要真实行为仍有可复核证据。
6. 作为多工作树开发者，我希望共享虚拟环境仍通过真实 Git 与 PowerShell 工作流复用，并在同链中验证正常清单更新。
7. 作为维护者，我希望只改一个领域时仍只选择其相关检查并使用独立缓存，以免所有检查被合成一个宽泛命令。

12. 作为维护者，我希望迁移结果区分通过、失败、跳过、未运行及未保护，不能以诊断结果或缓存掩盖缺失的验证证据。

## Implementation Decisions

- 不增加新的构建或验证入口。沿用现有统一入口、业务命令、公开接口和项目虚拟环境；当前没有真实构建产物，构建检查保持空，不运行占位构建充数。
- 采用一张完整纵向票据。新配置、检查分类、测试边界和工具自举相互耦合；票内按领域顺序实现，不用临时放宽真实清单制造中间绿色。
- 普通检查尽可能使用字节、字符串、表、数组和内存流；测试判断的是公开行为，不依赖临时目录是否创建等非必要实现细节。已授权删除的重复独立 JIT 检查无需重问，公式覆盖仍保留。其他低收益或极端物理用例应逐项说明原覆盖、替代覆盖和真实覆盖变化；若实质减少唯一覆盖或能力，必须先说明原因、收益、成本及影响并取得用户明确批准，不能仅说明后自行删除。
- 用户最新批准把 253 个真实测试函数收敛为 12 条领域核心链，取代早期仅 18→4 与 22→11 的中间矩阵方案。锁竞争、系统重试、链接矩阵、异常回滚、历史格式、重复 CLI 接线等物理覆盖按已披露清单退休；不宣称覆盖完全不变，生产防护不删除。新的未披露唯一能力取舍仍须批准。
- DuckDB 即使使用内存数据库也属于工具当前未覆盖的原生边界，只能进入聚焦真实检查。SQLite 内存数据库按工具现有窄适配运行；付费预览的文件数据库及一次性消费不能误列为普通内存行为。
- 对无关普通路径提前导入数据库的问题，优先在既有连接、查询或存储边界延迟实际导入，保留现有公开接口，不建通用数据库模拟框架，不改变生产行为。
- 三类真实环境是分类边界，不要求把所有领域合成三个巨型命令；也不预先扩成十个普通组加三个真实组。具体检查数量与逐项命令必须由实际测试归属和写入前完整清单证明。
- 最大外层并发保持4，按用户最新批准将工作树检查内部工作进程4改为2，其他检查不新增内并发。浏览器和工作树仍在既有串行阶段执行，不把4×2当作全部线程/子进程的实际峰值；资源另行披露。关闭自动加载 Pytest 插件；使用内部并行的命令显式加载已经声明的必要插件，不安装或升级业务依赖。
- 4×4是最初已验收方案，现用户批准4×2作为当前资源方案，不是每个检查或其他仓库的通用标准。精确配置按已有耗时与资源证据区分轻量内存组及重浏览器、数据库、环境准备检查，必要微调随最终清单确认；不为调并发新增调度器或大型基准测试。
- 按用户明确批准，采用新版的本机 60 秒总预算硬截止：快速与完整验证从入口起共用总截止，包含准备、缓存选择和执行；到期终止本次拥有的进程树、停止启动剩余检查并失败。配置明确保留总预算 60 秒并开启本机预算强制；原有单检查防挂边界不变，不新增 3 秒单测试限制。云端、拉取请求和持续集成沿用工具原策略，不将本机硬截止擅自扩展到这些场景。
- 保留既有按领域的路径选择和缓存输入；公共准备仅复用现有夹具，不建项目专用调度器。配置、共享夹具、命令依赖和实际动态读取范围必须出现在相应输入范围内。
- 不为共享准备保留多余基线层。同步在一链共用归档数据；工作树在同仓同环境完成初始化、共享与正常更新；两条量化 CLI 各复制所需小型公开源码并通过独立 .venv junction 复用现有环境。只读 SQL 各生成同 schema 的小数据，不读取大历史归档。可变输出按 case 隔离，不建跨进程缓存。
- 删除名不副实且重复的独立 JIT 检查项；风险缩放公式留在普通计算覆盖。生产即时编译开关、回调类型与正式编译契约保持不变，本次不新增真实 JIT 专项，也不宣称已验证编译。
- 按用户最新批准删除三个私有全历史条件复算，保留静态夹具结构、摘要连接和已有研究证据；不再自动证明三个完整历史场景精确一致，不造手动专项入口或隐藏 skip。
- 持续集成的自举工具与新配置兼容身份必须同时迁移，包括独立工具链工作流中硬编码的旧构建验证源码身份。保留现有正式生命周期流程，不擅自切换开发或发布模式；不提前重写另一工具的固定身份。
- 正式规格只在实施、验证、独立审查及规格交付门禁完成后通过官方规格流程应用。实施期间不改正式规格目录。

## Testing Decisions

- 目标产品是本仓库的统一验证能力。最高公开验收接缝是裸 `build-and-verify verify`，使用当前工作树、固定基线与明确执行地点；不能直接调用工具包内脚本或另造测试运行器代替。
- 开始开发门禁必须确认同一入口的红灯检查、绿灯复核与最终真实冒烟。逐领域定位可复用 Pytest 原生选择，但定向结果不等于统一入口验收通过。
- 新配置中普通检查必须产生实际保护证据，真实检查必须显示真实未保护角色。不得以真实检查的成功缓存替代普通保护证据，也不得因未知命令自动增加豁免。
- 普通检查覆盖配置、契约、解析、纯计算、错误门禁和必要静态读取；真实检查覆盖 12 条不能被内存替代的核心主路及链内数据完整性、幂等、一次性消费等必要断言。
- 核心量化主路沿用现有组合端到端夹具：共享行情导入、Parquet 固化、不可变快照、公开研究运行、结果重新读取与证据固化、海龟结果晋升；复用/冲突的可内存规则移入普通检查，重复 CLI 实测退休。不得把数个互不相连单元断言当端到端证据。
- 标准策略分析仍经既有公开运行与报告入口完成独立主路，保持其与单场景研究的职责边界，不因合并准备而互相调用。
- 归档与文档同步沿用已有公开命令或公开核心接口；浏览器只使用既有离线夹具和测试会话，不接触真实账号、付费下载或远端交易。
- 工作树环境验收仍真实运行 Git、PowerShell、项目虚拟环境及统一验证入口，以同一仓库和环境完成初始化、worktree 共享与正常清单更新；旧物理失败矩阵按批准退休。
- 检查归属审计必须列出保留、内存化、真实覆盖、去重和删除的旧测试意图；静默漏收、将跳过包装为通过、整组豁免均为不通过。
- 最终提供新配置的结构校验、固定基线快速验证、所确认场景的真实主路及独立审查证据。完整验证只在另获相应授权后执行；诊断模式不是正式通过证据。
- 既有 Ubuntu 工具链工作流在干净工作树执行快速验证时可能正常跳过；这种结果只作为工具链或结构证据，不能当作 Windows 正式验收，也不为此增加平台测试矩阵。
- 本机验收必须证明总预算为 60 秒、强制开关开启且执行地点如实声明，超时终止并失败；云端/持续集成仍按工具原策略产生性能告警与功能结果，不替本机证明硬截止。不能因一次运行超时而自动放宽预算、关闭强制开关或检查，或更换执行地点标识。

## Out of Scope

- 改变策略、回测引擎、交易语义、生产依赖版本、行情来源或结果契约。
- 将 Windows 专属生产能力移植到 Linux，或用兼容桩伪装 Windows 验收。
- 自研数据库模拟层、测试调度框架、安装器、构建脚本或新的验证入口。
- 新增真实 JIT 专项、删除生产 JIT 能力或修改现有正式编译要求。
- 扩建全面集成矩阵、重复极端物理测试或无依据增加验证范围。
- 合并、发布、直接推送主干、强制覆盖历史，以及访问或上传凭据和私有行情数据。
