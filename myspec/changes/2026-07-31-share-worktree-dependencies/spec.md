# 共享工作树 Python 环境

## 背景

Quant Research Lab（量化实验室）的 Python（脚本语言）虚拟环境位于主仓库根目录 `.venv`，当前约占 1.4 GB。工作树不应重复创建和安装该环境。工作树目录当前由 Claude（代码代理）放在 `.claude/worktrees/`，需要与技能仓库统一为仓库根目录 `.worktrees/`。

## 用户结果

开发者在主仓库根目录准备一次 `.venv` 后，可以在根目录 `.worktrees/` 创建和初始化任意工作树；工作树通过目录链接直接使用共享环境，无需再次下载或复制大型依赖。

## 需求

1. 仓库的工作树统一创建在根目录 `.worktrees/`，不再使用 `.claude/worktrees/`。
2. 主仓库根目录 `.venv` 是唯一 Python（脚本语言）依赖实体。
3. `scripts/setup-worktree.ps1` 在主仓库根目录运行时继续负责创建或更新根目录 `.venv`。
4. 该脚本在链接工作树内运行时，只把工作树的 `.venv` 链接到主仓库根目录 `.venv`。
5. 共享环境不存在时，工作树初始化必须停止，并提示先在主仓库根目录初始化；不得跨工作树修改主仓库环境。
6. 工作树与主仓库的依赖清单不一致时必须停止，不得静默复用或修改共享环境。
7. Build and Verify（构建与验证）仍只负责构建和验证，不负责安装依赖。

## 验证边界

- 从公开入口 `scripts/setup-worktree.ps1` 验证主仓库初始化、工作树链接、缺失环境停止和依赖清单不一致停止。
- 从 Build and Verify（构建与验证）入口验证通过共享链接完成真实主流程。
- 先保留因目标行为缺失而失败的检查，再实现使同一检查通过。

## 非目标

- 不复制或迁移当前正在使用的工作树。
- 不引入新的 Python（脚本语言）依赖管理工具。
- 不让工作树自动更新主仓库共享环境。
- 不为不同工作树创建独立大型虚拟环境。
